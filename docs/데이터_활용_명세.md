**공통 규칙**
- 수집되지 않은 날은 0이 아니라 빈 값(NaN)으로 둔다. 공백을 '급감'으로 잘못 읽지 않기 위해서다.
- 이상 탐지는 두 가지 방법으로 한다.
  - 같은 요일 기준(seasonal_z): 앞뒤 4주의 같은 요일 중앙값을 기대값으로 삼고, 잔차를 MAD로 표준화해 점수를 낸다. 뒤 4주 값도 쓰므로 돌아보는 분석이며, 데이터 마지막 4주의 점수는 새 데이터가 들어오면 달라질 수 있다.
  - STL 분해 잔차(robust_resid): 주기 7일로 분해한 뒤 남은 잔차를 쓴다.
- '제주 전체' 동반 변화는 설명하려는 읍면동을 뺀 나머지 합계로 본다. 한 곳의 큰 급증이 합계까지 끌어올려 섬 전체 흐름으로 잘못 읽히는 것을 막기 위해서다.
- '인근 읍면동' 동반 변화: 읍면동 중심점(정류소 좌표 평균, 없으면 AP 좌표 평균) 사이 거리로 가까운 3곳(15km 이내)을 이웃으로 두고, 이웃의 같은 신호 합계도 같은 날 크게 움직였는지 본다(본 서비스 임의 기준). 추자면처럼 15km 안에 이웃이 없으면 보지 않는다.
- 그날(앞뒤 1일 포함) 값이 없는 신호는 동반 변화를 '없음'으로 치지 않고 '자료 없음(확인 불가)'으로 따로 적는다. 예를 들어 와이파이는 2024-10~2025-03, 버스는 2025-01~03만 있어서 그 밖의 날짜는 확인할 수 없다(2026-11-15 수정, 판정 모델에 넘기는 근거 문장에도 반영).
- '작년 같은 시기' 반복: 52주 전 같은 요일 ±3일 안에 같은 방향 이상(점수 3 이상)이 있었으면 '매년 반복되는 변화일 수 있음'으로 근거에 붙인다. 기간을 2026-08까지 늘려 2025-04 이후 날짜에 쓸 수 있게 됐다.
- 이상일이 같은 방향으로 이어지면 한 구간으로 묶는다. 3일 이상이면 '지속 변화', 그보다 짧으면 '일시 급변'이다.
- 정류소·AP의 읍면동 매핑 결과(매핑 수, 실패 수)는 화면의 '데이터 품질' 탭에 나온다.

## 4. 이용조건·보안
- 허브 데이터는 제주데이터허브 이용약관을 따른다. 각 데이터 상세 페이지에는 데이터별 라이선스 표기가 따로 없다(2026-11-10 확인).
- 대회 게시판 답변 기준으로 허브 공개 원본, 전처리본, 소량 샘플은 출처와 전처리를 명세하면 제출물에 포함할 수 있다. 다만 허브 데이터목록 xlsx와 그 내용을 담은 DB는 제외해야 한다.
- 허브 API 키는 `.env`에만 저장하고 코드·제출물에는 넣지 않는다. 발급 방법은 `.env.example`과 설치 매뉴얼에 적었다.
- 분석과 원인 판정은 이 PC 안(Ollama 로컬 모델)에서 처리하며, 데이터를 외부 LLM으로 보내지 않는다.
- 화면은 `127.0.0.1`에서만 열린다.
- 저장한 브리핑은 `data/results`에 들어가며, 기본 설정으로는 화면을 끌 때 삭제된다.

## 5. 분석 흐름
1. **수집** (`app/ingest`): 허브 Open API → `data/cache/*.parquet`. 데이터별 일일 쿼터를 지키며 멈춘 페이지부터 이어받고, 끝까지 받은 요청 단위만 쓴다.
2. **위치 매핑** (`app/store`): 정류소(612)·AP(618) → 43개 읍면동. 버스(613)는 정류소 이름으로 연결한다(3장).
3. **신호 표** (`app/store`): 신호 4종을 날짜×읍면동 표로 합산한다. 수집되지 않은 날은 빈 값이다.
4. **이상 탐지** (`app/analytics/detect.py`): 같은 요일 중앙값(기본) 또는 STL 잔차로 점수를 내고, 점수가 기준(기본 3.5) 이상인 날을 이상일로 본다. 같은 방향으로 이어진 이상일은 한 구간으로 묶는다.
5. **근거 대조** (`app/agent/tools.py`): 같은 날 맥락(`check_context`: 기상, 공휴일, 축제, 입도객, 작년 같은 시기), 동반 변화(`find_co_movements`: 다른 신호, 제주 전체, 인근 읍면동), 외국인 국적별 변화(`nationality_mix`).
6. **원인 판정** (`app/llm/judge.py`): 근거를 문장으로 풀어 로컬 판단 모델(tev1)에 넘기고 원인 7개의 확률을 받는다. 모델이 없으면 규칙으로 판정한다.
7. **문장과 검증** (`app/report`, `app/agent/verify.py`): 템플릿으로 문장을 만들고, 검증기가 숫자·날짜·근거 id를 계산 결과와 대조한다. 통과한 문장만 화면과 브리핑에 나온다.
