## 3. 데이터별 사용 항목과 전처리
| 데이터 | 사용 항목 | 전처리 |
|---|---|---|
| 583 유동인구 | baseDate, city, emd, visitPop | 성별·연령대 행을 날짜·읍면동별로 합산 → 일 방문인구. city + emd를 43개 읍면동 이름으로 정규화. resdPop·workPop은 쓰지 않음 |
| 593 와이파이 | baseDate, apGroupName, userCount | AP그룹 → 읍면동(아래 매핑) 후 날짜·읍면동별 합산 |
| 613 버스 | baseDate, stationId, stationName, userCount | 요청 조건으로 승차·일반·카드만 수집했으므로 **현금·청소년 등은 빠진 값**이다. 613의 정류소ID(7자리)는 612의 ID(9자리)와 체계가 달라 겹치지 않는다(2026-11-11 확인). 그래서 기호를 뺀 정류소 이름이 612에서 한 읍면동에만 있을 때 그 읍면동으로 연결한다. 2025년 1~2월 이용자 수 기준 연결 89.5%, 같은 이름이 여러 읍면동에 있어 제외 6.7%(터미널 등), 매칭 실패 3.8%. 연결한 뒤 날짜·읍면동별로 합산 |
| 612 정류소 | stationId, stationAddress, longitude, latitude | 주소에서 읍면동 추출 → 실패하면 주소로 확정된 다른 정류소 중 2km 이내 가장 가까운 곳의 읍면동 → 그래도 실패하면 '매칭 실패'로 따로 집계(버리지 않음) |
| 618 AP 정보 | apGroupName, addressDong, latitude, longitude, category | 위와 같은 방식으로 AP별 읍면동을 정한 뒤, AP그룹의 대표 읍면동은 최빈값으로 정함. 페이지 순서가 호출마다 바뀌어 여러 번 받아 합집합(8회, 2,615개) |
| 579·578 기상 | observatoryName, baseDate, dailyRainfall, maximumWindSpeed / 관측소 좌표 | 읍면동(정류소 좌표 중심)에서 가장 가까운 관측소의 값을 씀. 일강수량 30mm 이상 또는 최대풍속 14m/s 이상이면 맥락으로 표시(본 서비스 임의 기준, 기상특보 기준 아님) |
| 580 입도객 | dtYearMonth, visitPurpose, visitorCnt | 목적별 합계 → 월 입도객. 주변 12개월 평균보다 ±5% 이상이면 성수기/비수기로 표시(본 서비스 임의 기준) |
| 공휴일 | 날짜, 이름 | 이상일의 전날·당일·다음날이 공휴일이면 맥락으로 표시 |
| 761 축제행사 | 콘텐츠명, 시작일, 종료일 | 원본에 장소 항목이 없다. 그래서 행사명 앞머리에 읍면동 이름이나 지명(예: '이호테우축제' → 이호동)이 **명시된** 경우에만 연결하고, 장소를 추측하지 않는다. '월대천'의 '대천'처럼 다른 단어 중간에 든 지명은 인정하지 않는다. 이름에 '취소'가 있는 행사와 7일을 넘는 행사(수주짜리 공원 축제 등)는 제외한다. 이렇게 해서 분석 기간 행사 161건 중 9건을 연결했다 |

**공통 규칙**
- 수집되지 않은 날은 0이 아니라 빈 값(NaN)으로 둔다. 공백을 '급감'으로 잘못 읽지 않기 위해서다.
- 이상 탐지는 두 가지 방법으로 한다.
  - 같은 요일 기준(seasonal_z): 앞뒤 4주의 같은 요일 중앙값을 기대값으로 삼고, 잔차를 MAD로 표준화해 점수를 낸다.
  - STL 분해 잔차(robust_resid): 주기 7일로 분해한 뒤 남은 잔차를 쓴다.
- 이상일이 같은 방향으로 이어지면 한 구간으로 묶는다. 3일 이상이면 '지속 변화', 그보다 짧으면 '일시 급변'이다.
- 정류소·AP의 읍면동 매핑 결과(매핑 수, 실패 수)는 화면의 '데이터 품질' 탭에 나온다.

## 4. 이용조건·보안
- 허브 데이터는 제주데이터허브 이용약관을 따른다. 각 데이터 상세 페이지에는 데이터별 라이선스 표기가 따로 없다(2026-11-10 확인).
- 대회 게시판 답변 기준으로 허브 공개 원본, 전처리본, 소량 샘플은 출처와 전처리를 명세하면 제출물에 포함할 수 있다. 다만 허브 데이터목록 xlsx와 그 내용을 담은 DB는 제외해야 한다.
- 허브 API 키는 `.env`에만 저장하고 코드·제출물에는 넣지 않는다. 발급 방법은 `.env.example`과 설치 매뉴얼에 적었다.
- 분석과 원인 판정은 이 PC 안(Ollama 로컬 모델)에서 처리하며, 데이터를 외부 LLM으로 보내지 않는다.
- 화면은 `127.0.0.1`에서만 열린다.
- 저장한 브리핑은 `data/results`에 들어가며, 기본 설정으로는 화면을 끌 때 삭제된다.
